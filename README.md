# ebaytrend — что сейчас разбирают на ebay.de

Инструмент под конкретную задачу: **найти б/у товар в диапазоне 80–500 EUR,
на который прямо сейчас идёт максимальный поток ставок**, чтобы закупать его
у ломбардов/секондов по всей Германии и перепродавать на Kleinanzeigen и Vinted.

Ключевая идея: количество ставок само по себе ничего не значит — важна
**скорость их прироста**. Лот с 30 ставками за 10 дней холоднее, чем лот
с 8 ставками за 4 часа. Инструмент считает `ставок/час` и сводит их в скор
спроса по нишам.

---

## Что уже сделано за тебя

* **23 ниши** с немецкими поисковыми фразами и сезонностью (`config/seeds.yaml`) —
  подобраны под ломбарды/секонды: профинструмент, кофемашины, бинокли,
  швейные машины, outdoor, Märklin, детское и т.д.
* **Автоотсев перегретых и скам-ниш** (`config/exclude.yaml`): iPhone, Garmin,
  AirPods, PS5, GoPro, DJI, Rolex, LV, кроссовки, Thermomix, аккумуляторы
  для e-bike. Там любой продавец без истории вызывает подозрение, и товар зависает.
* **Отсев мусора**: `defekt`, `Bastler`, `Ersatzteil`, `Konvolut`, `nur Karton`,
  `Anleitung`, `Hülle für`, реплики.
* **Два бэкенда**: скрейпер публичной выдачи и официальный eBay Browse API.
* **Метрика sell-through** — доля реально проданных среди завершённых лотов.
  Это главный ответ на «купят ли сразу».

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Быстрый старт

```bash
# 1. Посмотреть, какие ниши сейчас в сезоне (август → берём и сентябрьские)
python3 -m ebaytrend seeds

# 2. Первый скан: все сезонные ниши, только аукционы 80-500 EUR из Германии
python3 -m ebaytrend scan

# 3. Через 45-60 минут — второй проход. Только так считается честная дельта ставок
python3 -m ebaytrend watch --interval 45 --rounds 6

# 4. Отчёт
python3 -m ebaytrend report --md out/report.md --csv-dir out
```

Посмотреть формат вывода без сети:

```bash
python3 scripts/demo_offline.py     # синтетические данные, только для примера
```

## Команды

| Команда | Что делает |
|---|---|
| `seeds` | список ниш, сезон, метки, поисковые фразы |
| `scan` | один проход: выдача → фильтры → SQLite |
| `watch` | повторные проходы с паузой; даёт честные `ставок/час` |
| `report` | таблицы ниш и лотов, Markdown + CSV |
| `enrich` | для топ-лотов дотягивает число наблюдателей и время старта |
| `parse-file` | отладка парсера на сохранённой странице |
| `doctor` | состояние БД, сканов, блокировок |

Полезные флаги:

```bash
--seeds profi_akkuwerkzeug kaffeevollautomat   # только эти ниши
--tags vinted                                  # только то, что хорошо идёт на Vinted
--no-bulky                                     # без крупногабарита (нужен самовывоз)
--all-seasons                                  # игнорировать сезонность
--month 11 --lookahead 1                       # смотреть ноябрь-декабрь заранее
--mode sold                                    # скан завершённых лотов → sell-through
--min-hours-left 2                             # выкинуть снайпинг последнего часа
--delay 6                                      # медленнее, если eBay начал банить
```

## Как считается «ставок в час»

**`delta` (честно).** Разница ставок между двумя сканами, делённая на часы между
ними. Требует `watch` — минимум два прохода по одному лоту с интервалом от 18 минут.

**`est` (оценка из одного скана).** Из остатка времени восстанавливается
длительность аукциона (eBay даёт 1/3/5/7/10 дней), отсюда — сколько лот уже идёт,
и `ставки / прошедшие_часы`. Это верхняя граница: годится для первого прохода,
но `delta` точнее.

**`heat`** — `ставок/час` с поправкой на фазу аукциона. На eBay ставки идут волной
в последние минуты (снайпинг), поэтому лот с «20 ставок/час» за 10 минут до конца
получает коэффициент 0.35, а лот, который набирает ставки за сутки до конца, — 1.0.
Оценки методом `est` дополнительно множатся на 0.7.

## Как читать отчёт по нишам

| Колонка | Смысл |
|---|---|
| `скор` | сводный спрос 0–100: перцентильные ранги по 5 метрикам |
| `со ставками` | доля лотов со ставками **в поздней фазе** (<24 ч до конца). Свежие лоты без ставок метрику не портят |
| `медиана €` | медианная текущая цена — ориентир для продажи |
| `ставок/ч p75` | 75-й перцентиль скорости ставок в нише |
| `продаж %` | sell-through: доля проданных среди завершённых (нужен `scan --mode sold`) |
| `закуп до €` | потолок закупки в ломбарде = медиана × `buy_ratio` из seeds.yaml |

Веса скора: доля лотов со ставками 28%, медиана ставок 17%, скорость ставок 20%,
sell-through 25%, объём ниши 10%. Без данных о продажах веса перераспределяются.
Крупногабарит штрафуется на 8%, ниши с выборкой <5 лотов — на 25%.

## Рабочий цикл, который реально даёт результат

1. **`scan --mode sold` раз в неделю** по всем нишам — это даёт sell-through
   и медианную цену продажи. Именно эти два числа отвечают на вопрос
   «купят ли сразу» и «сколько платить в ломбарде».
2. **`watch --interval 45 --rounds 8` пару раз в неделю** — даёт живую скорость
   ставок и ловит всплески.
3. **`report --min-hours-left 2`** — смотришь топ ниш, а не топ лотов.
   Отдельный горячий лот — это шум; ниша с 80% лотов со ставками — это сигнал.
4. Идёшь в ломбард со списком: ниша → потолок закупки → медиана продажи.

### Сезонность (заложена в `seeds.yaml`)

Закупка идёт с опережением: то, что берёшь в конце августа, продаётся
в сентябре–октябре. Поэтому по умолчанию берётся текущий месяц **+1**.

* **сентябрь–ноябрь**: бензопилы и садовая техника, Dachbox и зимние колёса,
  Standheizung, осушители и обогреватели, тепловизоры, бинокли (охотничий сезон),
  outdoor-куртки и ботинки, музинструменты (начало учебного года)
* **октябрь–январь**: кофемашины, Hi-Fi и винтажное аудио, швейные машины,
  зимний спорт, домашний фитнес, Märklin и коллекционка, фарфор и серебро
* **круглый год**: профинструмент, ручной инструмент, фотооптика, детское,
  дизайн-мебель

Мотоэкипировку осенью, наоборот, **покупают дёшево и держат до марта** —
это отмечено в `note` у ниши.

## Бэкенды

### `html` (по умолчанию)

Парсит публичную выдачу `ebay.de/sch/i.html`. Ключей не нужно, но eBay
ограничивает скрейпинг: `/sch/` закрыт в robots.txt, при частых запросах
приходит капча. Поэтому по умолчанию — один поток, пауза 3.5 с + джиттер,
браузерные заголовки, ретраи с экспоненциальным бэкоффом.

Если поймал блокировку:

```bash
python3 -m ebaytrend scan --delay 8            # медленнее
python3 -m ebaytrend scan --cookie "$(pbpaste)"  # Cookie из браузера
export EBAYTREND_PROXY=http://user:pass@host:port
```

### `api` (официальный, рекомендуется для регулярного сбора)

```bash
export EBAY_CLIENT_ID=...       # App ID с developer.ebay.com
export EBAY_CLIENT_SECRET=...   # Cert ID
python3 -m ebaytrend scan --backend api
```

Плюсы: не банят, стабильная схема, есть `bidCount` и `itemEndDate`.
Минус: Browse API **не отдаёт проданные лоты**, поэтому `--mode sold`
работает только на `html`.

## Если eBay поменял вёрстку

Парсер намеренно не завязан на CSS-классы: он находит ссылки `/itm/<id>`,
поднимается к карточке и вытаскивает поля регулярками по немецкому тексту
(`Gebote`, `Versand`, `Noch 1T 04Std`). Это переживает переименования
`s-item` → `s-card` → что там дальше.

Если всё же сломалось — сохрани страницу выдачи из браузера и проверь:

```bash
python3 -m ebaytrend parse-file /path/to/saved.html
```

Команда печатает, сколько карточек нашлось и какая доля полей разобралась.
Правишь регулярки в `ebaytrend/textutils.py`, прогоняешь `pytest tests -q`.

## Структура

```
ebaytrend/
  textutils.py    разбор немецких цен, ставок, остатка времени
  html_parser.py  разбор страницы выдачи (устойчиво к смене классов)
  urls.py         сборка ссылок поиска: LH_Auction, _udlo/_udhi, LH_Sold, _sop
  http.py         rate limit, ретраи, браузерные заголовки
  backends/       html-скрейпер и официальный Browse API
  filters.py      отсев перегретых ниш и мусорных лотов
  storage.py      SQLite: items / observations / sold / scans
  velocity.py     ставок в час: delta и est
  scoring.py      агрегация по нишам, скор спроса
  report.py       таблицы, Markdown, CSV
  enrich.py       наблюдатели и время старта с карточки лота
  cli.py          команды
config/
  seeds.yaml      ниши, запросы, сезонность, потолок закупки
  exclude.yaml    стоп-бренды и мусорные слова
```

## Тесты

```bash
pip install pytest
python3 -m pytest tests -q      # 54 теста, все офлайн, сеть не нужна
```

Сквозной тест `tests/test_pipeline_e2e.py` прогоняет полный цикл
(выдача → фильтры → SQLite → второй скан → дельта ставок → отчёт)
на фикстурах, без обращения к eBay.

## Ограничения, о которых стоит знать

* Скрейпинг `/sch/` противоречит robots.txt eBay. Для регулярного
  сбора используй `--backend api`. Настройки по умолчанию заведомо
  вежливые — не снижай `--delay` ниже 3 секунд.
* Инструмент **не парсил живой ebay.de при разработке**: рабочее окружение
  сборки блокирует исходящие соединения к ebay.de. Парсер написан по
  фактической разметке выдачи и покрыт фикстурами; при первом запуске
  у себя прогони `parse-file` на сохранённой странице и убедись,
  что доля разобранных полей близка к 100%.
* Ставки на eBay концентрируются в последние минуты. Сравнивай лоты
  в похожей фазе (`--min-hours-left`), иначе топ забьётся снайпингом.
* Sell-through по завершённым лотам считается по тому, что eBay отдаёт
  в выдаче (обычно последние ~90 дней).
